# 材料力学实验教学闭环审核

> 本文是修改前的审核记录。后续已落地的改动和验证范围见 [实施记录](实验教学闭环实施记录-2026-10-09.md)。

日期：2026-10-09。范围：当前本地代码、运行中的 Spring Boot/Vue/Python 服务、教师和学生接口、隔离 H2 测试。

本轮先确认功能事实和架构缺口，不把已有页面等同于完成验收。尚未接入真实试验机和 USB 摄像头；浏览器截图审核等待替代浏览器方式确认。本报告中的页面结论在完成浏览器核查前属于源码审查，不声称已完成真人式界面验收。

## 总体判断

目标流程是完整的教学业务闭环，但当前实现尚未闭环。现有系统具备分组下发、数据解析、曲线、照片分析、课堂扣分、操作记录、个人报告及人工评分等基础。主要缺口集中在：数据究竟属于哪次实验、真实应变参数、最终扣分确认、历史课次入口、全班报告评阅与双报告查重。

目标流程：教师创建本次课堂并下发 → 学生确认组员 → 在厂商软件完成试验 → 关联本组本次原始文件 → 生成曲线 → 采集试件/断口照片 → 完成课堂操作记录 → 教师发布最终扣分 → 每名学生确认 → 归档 → 提交个人报告 → 查重/批阅/退回重交 → 发布成绩 → 历史查询。下一次正常实验建立新课次；补做建立原课次下的新尝试。

## 当前功能与缺口

| 步骤 | 当前情况 | 主要缺口与建议 |
|---|---|---|
| 1. 学生名单与分组 | 已有学号、姓名、班级字段；名单模板和导入支持班级；学生首页能显示组员 | 班级在任务、成员历史快照和报告列表中不统一。课次应有固定参与名单，不以学生当前分组反推历史 |
| 2. 教师下发 | 已有 taskId、实验时间、地点、小组；保存实验记录和成员 | 无独立课堂状态与结束确认流程；时间为自由文本；下发会被系统内其他未分组学生阻塞。应按本次参与名单校验 |
| 3. 厂商软件完成试验 | 平台不控制试验机，边界正确 | 真实厂商结束信号/文件写入完成、文件归属尚未现场验收 |
| 4. 原始数据导入 | 可解析 TestPilot MDB；后台也有通用表格预览与导入接口；保留源文件和哈希 | 学生界面当前主要是“开始采集”，综合实验自动取目录中最新 MDB，缺少本次文件选择/确认；同组其他子项重复文件有拦截，但跨组或跨课次误用尚未可靠防止 |
| 5. 力—位移曲线 | 已有曲线、单位、排序与有限点校验；原始 MDB 保留 | 应核对厂商力/位移单位、压缩符号、采样排序、完成文件条件；大文件需控制容量和读取开销 |
| 6. 应力—应变曲线 | 已有转换函数和拉伸曲线 | 固定直径 10 mm、标距 100 mm；设备位移作为伸长近似。未绑定真实尺寸/引伸计数据，压缩曲线未覆盖。不能按真实材料应变结果验收 |
| 7. 试件与断口 | 浏览器摄像头、照片上传、自动形貌分类、照片替换和保存已存在 | 图像区小；信息表单占空间；无摄像头设备选择；USB/远程 HTTPS 未验收。算法是 OpenCV 形貌规则，应保留“不确定/待复核”并用真实样本验证 |
| 8. 课堂扣分 | 默认 100 分，按有效扣分减分，教师可撤销；学生约每 10 秒读取一次 | 当前配置未确认、默认扣分项均为 0；缺少最终分数版本、逐人确认、待确认名单、纠错后失效重确认 |
| 9. 操作记录归档 | 保存归档快照，锁定实验数据和照片 | 本地复选框不是服务器确认记录；一人提交即小组归档；归档后分数仍可能变化。归档与确认应拆分 |
| 10. 个人报告 | DOC/DOCX/PDF 上传，草稿、正式提交、版本、退回、人工评分已存在 | 上传被操作记录归档完全阻塞；历史实验入口不完整；已批改报告导出未实现。可允许提前存草稿，最终提交受流程规则控制 |
| 11. 报告列表与批阅 | 当前小组列表、报告预览、教师评分/评语；存在自动评阅接口 | 未实现按参考图的全班课次总列表；普通桌面宽度下评分栏会到中栏下方；缺少批改时间/教师、批改中状态、前后学生切换、批改报告下载等完整支持 |
| 12. 查重 | 有个人分析文字片段比对；排除数字/配置模板；可输出百分比及短文本证据 | 仅本组内，按较晚提交对较早提交比较；无 A/B 双原文、高亮定位、片段切换和对比对象入口。参考图的双报告页尚未实现 |
| 13. 历史、补做和成绩 | 有 taskId、runId、parentId、attempt、报告 version；旧记录保留 | 学生页面隐藏大部分旧普通实验，仅保留当前任务和所有补做；多个课次同名难分辨。应区分“新课次”“补做尝试”“报告版本”，明确最终成绩归属 |

## “已核对分数但不能提交”的直接证据

当前学生 2025010101 的最新任务 `task_YjDvvVs7t7`，记录 `b23c16ee-6c39-3f98-ae5a-890cddb75b3e`：

| 子项 | 数据 | 照片 |
|---|---|---|
| 钢的拉伸 | 有 | 有 |
| 铸铁的拉伸 | 无 | 无 |
| 钢的压缩 | 无 | 无 |
| 铸铁的压缩 | 无 | 无 |

`Workspace.vue` 的提交按钮不仅判断核对复选框，还要求 `trialItems.every(t => t.dataReady && t.photoReady)`。因此该记录当前无法点击，属于现有四项齐全规则生效，而不是复选框未响应。后台 `TrialRecords.requireComplete` 也要求四项齐全。

解决方式不是直接取消校验：教师下发时明确本次必做子项；若本课要求四项，则界面显示四项进度和缺失项定位；若只做部分实验，则仅校验下发的必做项。当前系统固定下发四项，尚无可选范围。

另一个独立问题是版本冲突：`/classroom` 只返回扣分和分数，未返回 revision；学生自动刷新分数时不刷新提交用版本。教师新增扣分后，旧 revision 的归档请求会被拒绝为 409。之前移除全局错误条后，该失败缺乏反馈。建议使用操作按钮旁的短错误和重试入口，不恢复常驻说明条。

## 最终扣分确认方案

建议以每名学生实名确认为准，小组资料只保存一份。

1. 课堂进行中：操作分从 100 分计算，教师按组记录扣分；学生查看实时明细。
2. 学生资料齐全：可提交本组实验资料，不与“最终扣分确认”混成同一个复选框。
3. 下课前教师“结束记录并发起确认”：冻结本组评分版本，发布待确认分数。
4. 每名学生登录后点击“确认本次操作成绩”，服务器记录 sid、runId、评分版本、分数、扣分摘要及确认时间；如有异议，提交给教师处理。
5. 教师查看“已确认人数/应确认人数”、未确认名单和异议。缺席由教师补记原因，不能冒充学生确认。
6. 资料齐全且确认流程结束后归档。教师若纠错，生成新评分版本，使旧确认失效，要求重新确认并保留旧记录。

可用状态：进行中 → 待确认 → 已确认 → 已归档；异常分支包括异议处理中、已退回、待重新确认。保持课堂、组资料、个人确认、个人报告各自状态，避免一个 archived 布尔值承担所有含义。

## 试件与断口页面规划

从采集页面移除手填试件编号、设备编号、试验时间。后台仍保留来源标识和时间：来自文件、设备绑定和服务器拍摄时间，便于追溯。用于应力—应变计算的真实几何参数不能删除，应放在数据采集区或直接从厂商文件读取。

- 顶部：当前试验子项、摄像头选择、打开摄像头/拍摄/上传/重拍。
- 主区：大幅实时画面或原始照片，占主要内容宽度和可用高度，支持放大；拍摄前后保持同一位置，减少跳动。
- 右侧：分类结论、必要的形貌特征、复核状态；压缩项目显示变形/破坏形貌，不强求存在断口。
- 底部：上一项/下一项、保存状态。无需重复的功能介绍和长说明。
- 多摄像头须可选 USB 设备；权限被拒绝、设备掉线、分析失败时在操作位置给出短反馈，保留上传入口。

## 报告页面按三张参考图拆分

### A. 实验报告列表

以课次全部学生为范围，姓名/学号搜索，班级、小组、提交/批改状态筛选。

列：姓名、学号、班级、小组、提交时间、批改时间、批改教师、分数、状态、相似度、操作。

操作：原始报告、去批改、退回、查看、批改报告；相似度为进入对比的链接。没有报告或查重结果时显示“未提交/未检测”，不能伪造 0%。批改报告下载必须真正生成包含评分/评语的附件，不能放置空按钮。

### B. 报告批阅工作台

左栏：学生列表、待批改/已批改/进行中及数量、搜索。

中栏：仅实验报告原文，保留缩放、页码/滚动、原文件下载和版本；不复制参考图中的实验子任务问答。

右栏：辅助评阅结果（可用时）、教师评分与评语、退回、上一个/下一个、保存批改结果。普通教学电脑宽度也必须维持可用三栏，可临时收起全局菜单释放空间。

### C. 查重对比

顶部：对比对象和重复片段列表（片段长度、相似度、内容摘要）。

下方：当前报告 A 和对比报告 B 并排，作者和原文件入口；选片段时定位两侧对应位置，采用一致颜色高亮。

实现前需扩展当前比对结果：原文片段起止位置、文档页/段落映射、对比报告 ID/版本、排除模板后的有效文本量、比对范围和运行状态。现有去标点后的短字符串不能直接当作 PDF/DOCX 原文高亮坐标。先完成可核验文本对比，再完善双原文精确定位，不能用随机高亮伪装结果。

## 架构建议

保留 Spring Boot + Vue + Python 分析服务，不需要因本次需求拆成更多服务。先收敛业务模型和状态：

- 班级与学生：学生身份稳定，班级可维护。
- 课次：实验项目、日期时段、地点、教师、本次参与名单和必做子项。
- 分组快照：只属于本课次，之后重新分组不改动历史。
- 实验尝试：正常实验一次，补做另一次并关联原记录。
- 子项：钢拉伸/铸铁拉伸/钢压缩/铸铁压缩及各自参数、文件、照片、分析。
- 课堂扣分版本与个人确认：可审计、可纠错、可重新确认。
- 个人报告版本、比对任务与评阅：每位学生独立，明确草稿/提交/退回/评分。

现有 `experiment_runs.payload` 聚合了过多互相独立的数据，照片、同组成员动作、扣分和报告都争用一条 revision，应拆分评分版本和报告版本等并发边界。旧版 `students.status` 与新 `run.status` 并存，学生首页和新流程可能不一致，应统一查询来源。

跨机器部署时，服务端不能天然读取学生电脑的磁盘路径。若厂商软件与后端同机，可读取指定目录；否则需要受控共享目录、试验机侧采集代理或浏览器上传。USB 摄像头属于浏览器所在机器；局域网部署需要 HTTPS 与设备权限验证。

隐私边界也需收敛：当前 `/api/meta` 未登录即可返回学生名单；教师授权主要按角色而非其任教课次。多教师、多班正式部署前，应限制课次和学生资料访问范围。

补做名单存在上轮调整留下的边界：去掉班级下拉后仍默认选接口返回的第一个班级；若当前组跨班，其他班学生会被隐藏。应改为由当前课次参与范围/明确班级上下文确定，不能静默选择数组第一项。缺失班级占位符“—”也不能被当成一个真实班级。

## 验证结果

- 当前真实接口：教师和学生各可读取 6 条实验记录；仅 1 份历史正式报告，已人工评分 70。
- 当前设备目录状态：配置存在，但 sources 为空；不能宣称真实试验机文件采集已验收。
- 当前自动评阅：`enabled=false`、`gradingReady=false`；人工评阅路径存在。
- 当前扣分目录：`catalogConfirmed=false`，默认各项 0 分；使用前需教师设置正式规则。
- 原有后端测试：21 项，20 通过、1 跳过；曲线测试 2 项通过；前端构建通过。
- 隔离 H2 审核探针 3 项通过（验证的是缺口确实存在，不表示业务验收通过）：实时扣分后旧版本归档 409；归档快照 100 分但当前显示 85 分；一人归档后其他学生无需个人确认即可提交报告。
- 审核探针及运行结果保存在 `_tmp_workflow/audit-2026-10-09/`；临时测试类已从正式测试目录移除。

## 实施优先级与验收

P0：确认实际必做子项、修正提交阻塞与错误反馈；真实数据归属和几何参数；教师结束评分/学生实名确认/纠错重新确认；新课次与历史数据隔离。

P1：全班报告列表、三栏批阅、双报告查重；大图采集页、USB 选择；学生班级呈现、成绩回看、报告退回重提闭环。

P2：批改报告导出、成绩导出、权限细化、备份恢复、采集代理与现场设备联调。

完整验收至少覆盖：两个小组同时实验且不会互读文件；同一学生连续两个课次不串记录；老师扣分后学生刷新/确认均一致；确认后改分必须重新确认；单组员提交不代表他人签收；照片失败/设备文件缺失可恢复；报告退回生成新版本；对比双方和标记片段可追溯；次次运行均不产生假的成绩、查重率和分类结果。

页面采用真实业务表格、状态、筛选、操作和数据；删除装饰性副标题、重复流程介绍和冗长说明。保留单位、时间、文件限制、待办数量和必要的操作失败反馈，以紧凑字段或就地反馈呈现。所谓“去 AI 化”是去除模板化装饰和空泛文案，不是把真实结果和操作依据隐藏。
